i

승인 버튼과 완료 점검은 서로 다른 조건입니다. 승인 버튼이 보이는 것은 "권한이 있다"는 뜻일 뿐이고, 실제로 눌러 완료 처리하려면 오른쪽 완료 점검 목록이 전부 체크돼 있어야 합니다(정족수가 있는 유형은 정족수도 함께 채워야 합니다). 체크가 덜 됐는데 버튼이 잠겨 있다면 권한 문제가 아니라 점검 미완료입니다.

하위 업무 수정에서 바꿀 수 없는 것

담당자·하위 업무 유형·상위 업무는 등록 시점에 고정됩니다. 유형이 바뀌면 승인 필요 여부·승인자·정족수·완료 점검 항목이 통째로 달라지는데, 이미 등록 시점에 복사된 값이라 되돌릴 방법이 없기 때문입니다. 유형을 잘못 골랐다면 해당 하위 업무를 마감하고 새로 등록해야 합니다.

  3. 3
    오류·중복 행을 확인한다이 행들은 이관되지 않고 건너뜁니다 — 실행 전 사유를 꼭 읽어보세요.
  4. 4
    "되돌릴 수 없다는 것을 확인했습니다"에 체크 후 실행한다실행하면 정상 후보만 새 회원으로 등록됩니다.

역할 · 권한

/members/roles /members/roles/{id}/authorities /members/authorities

"회장", "국장", "박람회 총괄" 같은 역할을 만들고, 역할마다 어떤 권한을 줄지 정하는 화면입니다. 화면에 뜨는 모든 버튼·메뉴는 결국 이 권한 배열로 결정됩니다.

역할별 권한 부여 — 체크는 직접 부여, 파란 배지는 상위 권한에서 상속됨

개념의미
역할회원에게 붙는 이름표. 한 회원이 역할을 여러 개 가질 수 있고, 그중 하나를 "대표" 역할로 지정할 수 있습니다.
권한화면 기능 하나하나에 매달린 코드(예: WORK_MANAGE). 역할에 권한을 체크해야 그 역할을 가진 회원이 해당 기능을 씁니다.
상속권한 트리에서 상위 권한을 가지면 하위 권한도 자동으로 포함됩니다. "상위에서 부여" 배지가 붙은 항목은 체크를 해제할 수 없습니다.
!

묶음 권한만으로는 세부 권한이 열리지 않습니다. 예를 들어 어떤 역할에 "업무 쓰기" 권한만 주면 "업무 관리" 묶음 권한은 자동으로 따라오지 않습니다 — 화면은 정확히 그 회원이 가진 권한 코드만 보고 버튼을 그립니다.

i

이동은 감추고, 동작은 잠급니다. 갈 수 없는 메뉴는 사이드바에서 아예 보이지 않지만, 이미 보고 있는 화면 안의 버튼은 사라지지 않고 잠긴 채 남아 사유를 알려줍니다. 버튼에 마우스를 올려 이유를 확인하세요.

증상의미
버튼이 흐리게 잠겨 있다그 동작에 필요한 권한이 없습니다. 마우스를 올리면 어떤 권한이 필요한지 나옵니다.
멀쩡하던 화면에서 갑자기 403권한이 방금 바뀐 것입니다. 화면이 자동으로 최신 상태로 다시 맞춥니다 — 그래도 안 되면 새로고침하세요.
조회는 되는데 저장만 안 된다조회 권한과 쓰기 권한이 분리된 화면입니다(하위 업무 유형 관리 등). 정상 동작입니다.
